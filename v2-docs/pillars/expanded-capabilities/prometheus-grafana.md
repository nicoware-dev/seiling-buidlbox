# Prometheus & Grafana - System Monitoring

## Overview

Prometheus and Grafana provide comprehensive system monitoring and metrics visualization for Seiling Buidlbox. Prometheus collects metrics from all services, while Grafana provides beautiful dashboards for visualization.

## Features

- **Metrics Collection**: Collect metrics from all Seiling Buidlbox services
- **Visualization Dashboards**: Pre-configured Grafana dashboards
- **Alerting**: Configure alerts for high gas, service downtime, etc.
- **Sei-Specific Metrics**: Track blockchain-specific metrics (gas, transactions, RPC latency)
- **Service Health**: Monitor CPU, memory, and response times

## Setup

### Enable Prometheus/Grafana

1. **Set environment variables in `.env`:**
   ```bash
   ENABLE_PROMETHEUS=yes
   GRAFANA_ADMIN_USER=admin
   GRAFANA_ADMIN_PASSWORD=<auto-generated>
   ```

2. **Deploy services:**
   ```bash
   ./bootstrap.sh
   ```

### Services Included

- **prometheus**: Metrics collection server (Port 9090)
- **grafana**: Dashboard visualization (Port 3000 internally, 8005 via proxy)

## Access

- **Prometheus**: http://localhost:9090
- **Grafana**: http://localhost:8005 (if Caddy enabled) or http://localhost:3000
- **Default Grafana credentials**: admin / (password from GRAFANA_ADMIN_PASSWORD)

## Adding Metrics to Services

### Exporting Metrics

Services can expose Prometheus metrics by implementing a `/metrics` endpoint:

**Example for Node.js:**
```javascript
const promClient = require('prom-client');

const register = new promClient.Registry();
promClient.collectDefaultMetrics({ register });

app.get('/metrics', async (req, res) => {
  res.set('Content-Type', register.contentType);
  res.end(await register.metrics());
});
```

### Scraping Configuration

Add scrape jobs in `docker/prometheus/prometheus.yml`:

```yaml
scrape_configs:
  - job_name: 'my-service'
    static_configs:
      - targets: ['my-service:8080']
    metrics_path: '/metrics'
```

## Grafana Dashboards

### Default Dashboards

1. **Seiling Buidlbox Overview**: General service health and status
2. **Service Metrics**: Individual service performance
3. **Sei Blockchain Metrics**: Gas usage, transaction counts, RPC latency

### Creating Custom Dashboards

1. Access Grafana at http://localhost:3000
2. Login with admin credentials
3. Create new dashboard
4. Add panels with Prometheus queries

### Example Queries

**Service uptime:**
```promql
up{job="n8n"}
```

**Request rate:**
```promql
rate(http_requests_total[5m])
```

**Response time:**
```promql
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))
```

## Alerting

Configure alerts in Prometheus or Grafana for:
- High gas prices
- Service downtime
- High error rates
- Resource exhaustion (CPU/Memory)

**Example alert rule:**
```yaml
groups:
  - name: seiling_alerts
    rules:
      - alert: HighGasPrice
        expr: sei_gas_price > 1000000000
        for: 5m
        annotations:
          summary: "High gas price detected"
```

## Troubleshooting

### Prometheus Not Scraping

1. Check service endpoints:
   ```bash
   curl http://service-name:port/metrics
   ```

2. Verify scrape configuration in `prometheus.yml`

3. Check Prometheus targets:
   - Access http://localhost:9090/targets
   - Verify all targets are UP

### Grafana Not Loading

1. Check logs:
   ```bash
   docker logs seiling-grafana
   ```

2. Verify datasource connection:
   - Access Grafana UI
   - Check datasource configuration
   - Test connection to Prometheus

### High Resource Usage

- Adjust scrape intervals in `prometheus.yml`
- Reduce metric retention time
- Limit number of scraped services

## Performance

- **Scrape Interval**: 15 seconds (configurable)
- **Retention**: 30 days (configurable)
- **Resource Usage**: Low overhead (<100MB RAM per service)
